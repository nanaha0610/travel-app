# 保存動画の一覧

下部バーの「動画一覧」で、ログインしている本人の保存動画を、保存した順の新しいものから表示します。旅行名・場所名・撮影日時が付いています。公開投稿や他の人の動画はまだ対象にしていません。

## 操作

- 上下スクロール、または「前の動画」「次の動画」で切り替えます。一覧枠にキーボードのフォーカスがある場合は上下矢印キーも使えます。
- 表示中の1本だけを読み込み、消音で繰り返し再生します。音声は動画プレイヤーのコントロールで切り替えます。
- 自動再生が許可されない場合は「再生する」を押します。
- 動画を切り替えたり画面を離れたりすると、前の動画を停止して再生用URLを解放します。別タブへ移った場合も停止し、戻った際は再生ボタンから再開します。
- 20件ずつ一覧を読み込みます。「さらに動画を読み込む」で続き、「一覧を更新」で新しい保存動画を確認できます。
- 動画がない場合は撮影画面への案内、通信失敗時は再読み込みボタンを表示します。

## 接続とDB

既存の共通ログインと `VITE_API_BASE_URL` を使います。サーバーの `ALLOWED_ORIGINS` は画面のURLに合わせてください。DB構造の追加変更はありません。動画保存機能の `trip_places` / `trip_videos` が必要です。まだ作成していない環境では接続確認後、serverで `npm run db:init` を実行します。

追加API：`GET /api/videos`（Bearer認証必須）

- 成功時：`{ videos: [...], nextCursor: "動画ID" または null }`
- 本人の旅行に紐づく動画メタデータのみ。各項目は `id`, `captured_at`, `mime_type`, `byte_size`, `place_name`, `trip_id`, `trip_title`。
- 動画本体は含みません。表示する1本だけ既存の `GET /api/videos/:videoId/content` で取得します。
- 続き：`GET /api/videos?before=nextCursor`。最大20件、保存IDの降順。取得途中で新しい動画が保存されても、続きの動画が飛ばない方式です。
- 無効なカーソルは400、未ログインは401。所有者は認証情報から決めます。

## 確認手順

1. サーバーと画面を起動し、ログインする。
2. 撮影画面で2本以上保存し、動画一覧に移動する。
3. 旅行名・場所・撮影日時、消音再生、前後切り替え、スクロールによる切り替えを確認する。
4. 別タブや別画面へ移動し、動画が停止することを確認する。
5. 別アカウントでログインし、他人の動画が表示されないことを確認する。
6. 複数旅行に合計21本以上保存した環境では、続きの読み込みを確認する。

自動テスト：serverで `npm test`、プロジェクト直下で `node --test --test-isolation=none tests/api-client.test.mjs`。ビルドは `npm run build`（制限されたWindows環境では `-- --configLoader native` を追加）。

実DBへの保存・取得、実ブラウザーの動画デコードとスマホのスクロール動作は別途確認してください。仮想DOMテストや代替DBのAPIテストだけではこれらを保証できません。
